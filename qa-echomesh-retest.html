SEVERE — BUG 01

External share links are dead

Created a password-protected share link from the Share tab. The UI shows it proudly with Copy and Revoke buttons, creation date 10/29/2026, expiry 11/5/2026. Visiting the link gives “Link Not Found — The link you are trying to access does not exist.”

Repro

  1. Log in → event → form → Share tab → Create share link
  2. Set password ShareTest123, submit. Link appears: /shared/ff329083…25df4e
  3. Open that URL logged out. First load: blank page, empty title. After settling: Link Not Found.

Evidence

  • Screenshots: link displayed in-app vs. Link Not Found page on the URL.
  • Browser console is clean — no JS crash, only a font 404 and a manifest warning. The page renders its error state correctly, so the frontend is fine; the lookup behind it resolves nothing.

How bad

Feature-level kill. Anyone you send a “secure results link” to hits a dead page, and the app told you the link was live. Suspects, in order: token/ID mismatch between create and read, row not committed or RLS-blocked on read, wrong route param. Check what the create endpoint stores vs. what /shared/[token] queries.

SEVERE — BUG 02

AI Copilot is down, and it leaks raw provider JSON

Sent “How many submissions do we have?” The thread is created, then the answer slot fills with a raw error string instead of a reply:

PROVIDER_ERROR:402:{"error":{"message":"Insufficient credits. Add more using https://openrouter.ai/settings/credits",...}}

Two failures, not one

  • Shared OpenRouter key is out of credits. Copilot is 100% down for every team that has not wired BYOK. The Settings page says “Shared server key. No setup needed” — that promise is currently false.
  • Raw provider JSON is rendered to the user. Nobody outside engineering should ever see PROVIDER_ERROR:402 plus a billing URL. Catch it, show “The AI service is unavailable right now,” log the rest.

How bad

Whole Copilot surface is decorative until credits or messaging change. Top up the shared key or gate the UI honestly (“AI unavailable — add a team key in Settings”), and sanitize provider errors everywhere, not just this call.

HIGH — BUG 03

Results row Delete does nothing

Clicked Delete on a submission row in two separate sessions. No confirm dialog, no toast, no error, row still there on re-read. The button is visually alive and completely inert.

How bad

Data hygiene is broken — test and junk submissions cannot be removed through the UI, which also means the Trash restore/permanent-delete flow is untestable and unverified. Likely a missing handler or a confirm modal that never mounts. Wire it or remove it; a dead destructive button erodes trust fast.

MINOR

Small stuff

  • Empty event name submits silently. Pressing Enter with a blank Event Name does nothing — no error, no shake, no hint. The * says required; say it out loud when it fails.
  • Login takes 20–25 seconds headless before the dashboard lands. Everything downstream pays this tax. If it is a cold start, fine — but measure it; if it is a waterfall of auth calls, fix it.
  • Cosmetic console noise: source-serif-4-latin.woff2 404s, manifest orientation value warning. Harmless, but free to silence.
  • Duplicate-question footgun (mine, not yours): my retries created two identical “Your Email” questions on the slide. A real user double-clicking Save could do the same — consider disabling Save while the request is in flight.

HOW THE TESTING ITSELF STRUGGLED

Honest log of where the harness fought back — some of it is your app, most of it was my tooling, all of it cost sessions:

  • Async waits. Login and modal submits outrun fixed sleeps. Added a wait <secs> command to the CLI mid-test; 20–25s after login, 3–5s after submits. Without it, snapshots race the SPA and read stale states.
  • Ambiguous selectors. button.btn.btn-primary matches Sign In, New Event, Create Form, Add Field — first-match clicking is a loaded gun. Added click_text (click by visible text); that is what unblocked the tabs.
  • Preview opens _blank. Headless driver stays on the old tab with no tab-switch command, so Preview looked broken until I pulled the href directly. Multi-tab flows need tab support in the CLI.
  • Hidden-input trap. Typing into a not-yet-opened modal input reports success, then ENTER goes nowhere. Burned a full session. The CLI should assert visibility, not just presence.
  • Stale elements after login navigation. The SPA re-renders post-auth; any element grabbed across that boundary dies. Settling waits fixed it.
  • Duplicate test data. Retries created twin questions. Harmless here, but it is exactly how a double-clicking user would pollute a form — hence the disable-while-saving note above.

SUGGESTED FIX ORDER

  1. Make /shared/[token] resolve what create stores — or stop showing the link until it does. (Bug 01)
  2. Top up the shared OpenRouter key and wrap provider errors in a human message. (Bug 02)
  3. Wire the Delete confirm path, then exercise Trash restore + permanent delete. (Bug 03)
  4. Validation feedback on empty required fields; measure the login waterfall; silence the font/manifest 404s.
